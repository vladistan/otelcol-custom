Where the time goes (redis, logshape-branch; pprof of go test -bench=LogshapeVsBlock/redis/impl=logshape-branch -benchtime=6000x -cpuprofile)

  ConsumeLogs 6.94 s cum: route 5.10 s; of it the branch parse 3.73 s (regexp FindStringSubmatch 2.06 s) and claims 0.38 s
  groups.add 1.55 s (fmt.Sprint of the resource attributes, 0.85 s): the regroup key is built for every record whose
  branch set service.name; the scratch LogRecord.CopyTo 0.45 s
  Allocations (pprof alloc_objects, one run of the same benchmark): CopyTo 16.9%, safeParse 12.3%, groups.add 6.1% of 97.8 million
  Each branch runs its regex twice on the line (claims, then parse) and copies the record, resource and scope before it parses.

Limits: the sample files hold 1 to 8 lines each, cycled to 1000 records, so a format with few lines is a narrow input.
The uvicorn block handles 3 of 5 sample lines (changed 0.60); logshape handles all 5, so its extra work is part of its time.
The block-aligned rows show the gap is not the options: nginx 1.01, sentry 0.90 and logrus 0.99 of the block median.
